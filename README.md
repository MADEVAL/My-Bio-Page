# Self-Hosted Link-in-Bio with MCP Server

A production-ready, content-driven link-in-bio page built on PHP 8.5. One JSON file powers both languages, the meta tags, JSON-LD, the sitemap, and a 12-tool MCP server for AI-assisted content changes.

No framework. No runtime dependencies. No build step.

---

## Why this exists

Most link-in-bio tools are hosted, locked down, and require a subscription for basic customization. This project takes the opposite approach:

- you own the server and the content;
- the page is plain HTML generated by PHP;
- metadata and structured data come from the same content tree;
- an MCP endpoint lets agents add, reorder, hide, and edit links safely;
- every write is validated, backed up, and revision-controlled.

The result is a small, fast, SEO-friendly page that can be edited by a human or an AI client without touching templates.

## How it works

```text
request ──► web server ──► public/index.php ──► App ──► Cache ──► Renderer ──► HTML
                                │                              ▲
                                └──► Content (app/content/site.json)
```

- **One content source.** `app/content/site.json` holds both languages, all links, all metadata, and settings.
- **Rendered once, then cached.** The cache key includes the content revision, the seed, the template, every PHP source file, and the public CSS/JS, so a deploy or edit invalidates itself.
- **Writes are safe.** Every mutation validates the whole tree, copies a backup, writes atomically under `flock`, and appends to an audit log.
- **MCP uses the same path.** There is no second admin mode and no parallel write path.

## Quick start

Requirements: PHP 8.5 with Xdebug only for coverage runs.

```bash
php -S 127.0.0.1:8123 -t public tests/router.php
```

Open `http://127.0.0.1:8123/`.

`tests/router.php` mirrors the production rewrite rules, including `/mcp`, pretty URLs, and dotfile denial.

The first request provisions an MCP token in `app/bio.token` if the application directory is writable. For production, pre-create the token as described in [Deployment](#deployment).

## Content model

A link item is intentionally small:

```json
{
  "id": "telegram",
  "type": "link",
  "href": "https://t.me/example",
  "icon": "telegram",
  "order": 1,
  "visible": true,
  "title":    { "en": "Telegram Channel", "ru": "Телеграм-канал" },
  "subtitle": { "en": "@example",         "ru": "@example" }
}
```

Supported item types: `link`, `featured`, `project`, `social`, `email`.

Supported section layouts:

- `cards` — every visible item is rendered as a card;
- `social` — every visible item is rendered as a square social button;
- `mixed` — social items go to a grid, everything else to cards.

Icons come from a fixed inline-SVG registry. An item can use `logo` instead of `icon`, including social buttons.

Validation rejects invalid content before it reaches disk: bad schemes, unsafe asset paths, duplicate IDs, empty required translations, impossible dates, invalid GA4 IDs, and inconsistent email items.

## MCP server

Endpoint:

```text
POST https://your-domain.com/mcp.php
Authorization: Bearer <MCP_TOKEN>
Content-Type: application/json
```

JSON-RPC 2.0 over Streamable HTTP. JSON responses only, POST only, no SSE stream.

```bash
curl -s https://your-domain.com/mcp.php \
  -H "Authorization: Bearer $MCP_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18"}}'
```

### Tools

| Tool | Purpose |
|---|---|
| `get_content` | Whole content tree and current revision |
| `get_schema` | Complete JSON Schema for the content tree |
| `list_sections` | Sections, labels, layouts, item counts |
| `list_links` | Links filtered by section or visibility; `lang` localizes titles |
| `create_link` | Add a link at an optional position |
| `update_link` | Patch title, subtitle, href, type, icon, visibility |
| `move_link` | Move between sections or positions |
| `set_visibility` | Hide without deleting |
| `delete_link` | Soft delete by default; `hard: true` removes it |
| `update_settings` | Email, theme, footer year and GA4 |
| `preview` | Render either language without touching the cache |
| `publish` | Drop the HTML cache |

Every mutation accepts `rev`. A stale revision returns a conflict instead of silently overwriting a newer change.

### Authentication

The token is read from the first available source:

| Source | Notes |
|---|---|
| `MCP_TOKEN` in the PHP-FPM pool environment | Nothing on disk |
| `BIO_TOKEN_FILE` | Explicit path outside `public/` |
| `app/bio.token` | Generated on first use when `app/` is writable |

There is no `.env` fallback. Empty token means the endpoint is locked.

Recommended production setup:

```text
/var/www/example/app/bio.token   # 64 hex characters, mode 0600
```

Rotate by deleting the file and provisioning a new one. If `app/` is not writable, the application will not create it automatically.

### Client setup

All clients need the same two values:

```text
URL:           https://your-domain.com/mcp.php
Authorization: Bearer <64 hex characters from app/bio.token>
```

Keep the token in an environment variable. On Windows:

```powershell
setx BIO_TOKEN "<token>"
```

#### OpenCode V2

Project or global `opencode.jsonc`. `oauth: false` is required because this endpoint is header-only.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "bio": {
        "type": "remote",
        "url": "https://your-domain.com/mcp.php",
        "oauth": false,
        "headers": {
          "Authorization": "Bearer {env:BIO_TOKEN}"
        }
      }
    }
  }
}
```

```sh
opencode mcp list
```

`{env:BIO_TOKEN}` is the **name** of the environment variable, not the token itself.

#### OpenClaw

`~/.openclaw/openclaw.json`. `transport` must be explicit, otherwise OpenClaw falls back to SSE.

```json
{
  "mcp": {
    "servers": {
      "bio": {
        "url": "https://your-domain.com/mcp.php",
        "transport": "streamable-http",
        "headers": {
          "Authorization": "Bearer ${BIO_TOKEN}"
        }
      }
    }
  }
}
```

Or through the registry:

```sh
openclaw mcp set bio '{"url":"https://your-domain.com/mcp.php","transport":"streamable-http","headers":{"Authorization":"Bearer ${BIO_TOKEN}"}}'
openclaw mcp doctor bio --probe
```

#### Claude Code

```sh
claude mcp add --transport http bio https://your-domain.com/mcp.php \
  --header "Authorization: Bearer $BIO_TOKEN"
```

Or `.mcp.json` at the project root. The file can be committed; the secret stays in the environment:

```json
{
  "mcpServers": {
    "bio": {
      "type": "http",
      "url": "https://your-domain.com/mcp.php",
      "headers": {
        "Authorization": "Bearer ${BIO_TOKEN}"
      }
    }
  }
}
```

`type` is not optional: an entry with a `url` and no `type` is read as a stdio server.

### Connection troubleshooting

| Symptom | Likely cause |
|---|---|
| `401` | Wrong token, or the token was rotated |
| `401` with `Bearer {env:...}` in config | The token was pasted inside the braces |
| `405` | The client probed with `GET`; this endpoint is POST-only |
| Client starts OAuth | The `Authorization` header is missing; check the header and `oauth: false` |
| 12 tools listed but none visible | Client-side tool filters or permissions |

## Deployment

PHP-FPM is the supported runtime. Apache 2.4 works through `public/.htaccess`; nginx needs the usual `try_files`.

Document root: **`public/`**. Never point the web server at the repository root or at `app/`.

### Nginx

```nginx
root /var/www/example/public;
index index.php;

location / {
    try_files $uri $uri/ /index.php?$query_string;
}

location = /mcp {
    rewrite ^ /mcp.php last;
}

location ~ \.php$ {
    include fastcgi_params;
    fastcgi_pass unix:/run/php/php8.5-fpm.sock;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_param HTTP_AUTHORIZATION $http_authorization;
}
```

### Apache

Point `DocumentRoot` at `public/`, enable `AllowOverride All` (or at least `FileInfo`, `Options`) and `mod_rewrite`. `public/.htaccess` handles `/mcp`, pretty URLs, directory listing, and dotfiles.

### Routes

| URL | Result |
|---|---|
| `/` | EN |
| `/?lang=ru` | RU |
| `/index.php?lang=ru` | RU |
| `/ru.html` | RU (rewritten to `index.php`) |
| `/mcp.php` | MCP endpoint |
| `/mcp` | Alias (rewrite or Apache rule) |
| `/robots.txt` | Generated from `settings.siteUrl` |
| `/sitemap.xml` | Generated from content |

Verify after deploy:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://your-domain.com/          # 200
curl -s https://your-domain.com/index.php?lang=ru | grep -c 'lang="ru"'    # 1
curl -s -o /dev/null -w '%{http_code}\n' https://your-domain.com/mcp.php   # 405
```

### Files and permissions

Deploy both `public/` and `app/`:

```bash
rsync -a public/ user@host:/var/www/example/public/
rsync -a \
  --exclude 'bio.token*' \
  --exclude 'content/site.json*' \
  --exclude 'content/backups/' \
  --exclude 'content/.audit.jsonl' \
  --exclude 'cache/' \
  app/ user@host:/var/www/example/app/
```

The GitHub workflow stages `app/` and `public/` into one `deploy/` directory and rsyncs that directory. `DEPLOY_TARGET_OCAT` must point to the site root that should contain both, for example `/var/www/example/`.

PHP-FPM needs write access only to `app/content/` and `app/cache/`. The token is a file, not a directory. Do **not** give the web user write access to `app/` or the repository root: with write access to the parent directory, a compromised PHP process could replace the application.

```bash
install -d -o www-data -g www-data -m 0775 /var/www/example/app/content /var/www/example/app/cache
php -r 'echo bin2hex(random_bytes(32)), "\n";' > /var/www/example/app/bio.token
chown www-data:www-data /var/www/example/app/bio.token
chmod 600 /var/www/example/app/bio.token
```

If the token cannot be created or read, MCP answers `401` and the public site keeps working.

### Cache

The rendered HTML cache is invalidated automatically when any of these change:

- content revision;
- content seed;
- page template;
- `public/styles.css` or `public/script.js`;
- any file in `app/src/`.

`publish` is only needed after an out-of-band content edit that does not bump `rev`.

## Security model

- Bearer token read from `MCP_TOKEN`, `BIO_TOKEN_FILE`, or `app/bio.token`; compared with `hash_equals`.
- `public/` is the only document root. Source, templates, content, cache and token are outside it.
- Whole-tree schema validation before every write; invalid content never reaches disk.
- Atomic writes (`tmp` + `rename`) under an exclusive lock; short writes are rejected.
- Backup of the previous revision before every write; the last 20 are kept as `site-revNNN.json`.
- Audit log at `app/content/.audit.jsonl`.
- CSP, HSTS, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy` and `X-Content-Type-Options`.
- All user content is escaped; JSON-LD uses `JSON_HEX_TAG`; only `http(s)` and `mailto` links are accepted.
- Google Fonts is not loaded; Inter is self-hosted from `public/assets/fonts/`.

### Recovery

```bash
cp app/content/backups/site-rev003.json app/content/site.json
rm -f app/cache/*.html app/cache/*.key app/cache/*.tmp
```

## Analytics

GA4 is off by default. An empty `ga4` string means no tag and no request to `googletagmanager.com`.

```json
"settings": { "ga4": "G-XXXXXXXXXX" }
```

Switch it at runtime through MCP:

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"update_settings","arguments":{"ga4":"G-XXXXXXXXXX"}}}
```

Disable with `"ga4": ""`. `UA-` properties are rejected.

GA4 sets cookies, so where consent is required this switch alone is not enough. The page does not ship a consent banner.
